# SCHEMA · 文案出稿工作台操作手册

> ⚠️ 这是给 **AI** 看的「行为契约」，不是给人看的文档。
> 每次**写内容**前，AI 都先读本文件。
> **骨架稳定、风格可换**：换项目 / 换老师，只需替换 `5-个人风格` 里的两个文件，本手册结构不变。

---

## 一、目录定义（0–5 六个目录，每个放什么）

| 目录 | 名称 | 放什么 | 层 |
|---|---|---|---|
| 0 | 选题池 | 想法、热点、待写选题，灵感先丢这里 | Raw |
| 1 | 素材库 | 从知识库调来的素材、案例、金句、数据 | 素材 |
| 2 | 内容生产 | 一个选题一个文件夹，存文章.md + 排版.html | 产出 |
| 3 | 标题库 | 标题公式、历史数据规律、实战标题收集 | 资产 |
| 4 | 发布追踪 | 每篇稿子一行，发布后回填数据复盘 | 资产 |
| 5 | 个人风格 | 语言风格、金句、观点、故事、红线话术 | 风格 |

## 二、出稿流程（六步，每次写稿前按顺序走）

1. **选题，先判断模式**：
   - 外部知识驱动型 —— 知识主要来自素材库 / 知识库
   - 个人实践驱动型 —— 知识主要来自个人实测 / 案例 / 方法论
   - 混合型 —— 外部知识解释问题，个人实践负责落地
   - 判断依据：这次要讲的内容，知识主要来自谁。
2. **调素材**：读 `1-素材库` 对应主题，重点取每个知识页的「出稿素材」区块（一句话观点 / 开头钩子 / 核心金句 / 可展开案例）。
3. **skill 出正文**：用写作 skill 生成正文。skill 会先检查材料够不够（够 5 件以上才写长稿，不够它会先问）。正文出来是纯文本。
4. **加排版层**：在 skill 正文文字**不动**的前提下加视觉标记：
   - 小标题：一个逻辑块切一个，从正文提炼，不新增内容
   - 加粗：克制，只标最有冲击力的数据、最关键结论句
   - 亮点卡：从「核心金句」里挑最能代表全文观点的一句（AI 判断，两句话都合适才问用户）
5. **起标题**：用标题 skill 出 1 主标题 + 2 备选，外标题和封面标题要视角错开。
6. **排版 + 交付**：生成排版 HTML + 预览，交用户确认。**不擅自发布。**

---

## 三、调用顺序（写内容前读什么）

1. 先判断选题模式
2. 读 `1-素材库` 对应素材（优先「出稿素材」区块）
3. 读 `5-个人风格/个人风格文档.md`（语言风格 → 金句 → 观点 → 故事 → 私域话术）
4. 读 `5-个人风格/红线话术文档.md`（不说的词、不用的句式）
5. 根据需要读 `3-标题库`、`4-发布追踪`（看同类表现）
6. 区分公众号长文与视频号口播后再动笔

**读完才动笔。**

## 四、排版红线（通用，公众号粘贴不坏）

> 不同平台的排版支持度不同，这是公众号场景踩过的坑，通用适用。

1. **多列 / 横排布局只用 `<table>` 表格**（公众号原生支持）。不要用 `display:flex`、`overflow-x:scroll`、`inline-block`+`white-space:nowrap`——粘贴到公众号编辑器会被清洗，塌成竖版。
2. **禁用横向滚动**（`overflow-x: scroll`），公众号编辑器不支持。
3. **标注里的数字必须跟实际卡片 / 条目数量一致**（写"4 个章节"就是 4 个，不能写"3"却显示 4 个）。
4. **排版 HTML 是成品**，不要用可视化编辑器打开并保存——会弄丢 head/style/script 骨架，复制按钮失效。改文字一定改源稿。

---

## 五、来源边界（写稿时的雷区）

- 一般观点经过理解和重组后，不必在正文反复写「某博主认为」。
- 以下内容需标注来源：
  - 直接引用原话
  - 独家案例、数据、调研
  - 明显原创的概念或方法论
  - 需要来源增强可信度的事实
- **不能把别人的经历写成用户亲历，不能把没做过的事写成"我做过"。**

---

## 六、冲突处理（Lint）

- 新素材与既有认知矛盾时：**标注 ⚠️ 并说明分歧，不直接覆盖**。
- 定期检查：孤儿页、断链、过时内容，列清单确认后再修。

---

## 七、红线（写内容绝不触碰）

> 详见 `5-个人风格/红线话术文档.md`，通用示例：
- 不写具体收入数字，不用「轻松赚钱」等夸大词
- 引导留资不说「私信我」，改说「评论区找我聊」（防限流）
- 去空话：赋能 / 闭环 / 抓手 / 底层逻辑（除非本人真这么讲）
- 有真实案例或对话片段，有清晰个人判断，留一个互动问题
